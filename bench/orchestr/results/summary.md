# orch-bench 首期结果（pilot, n=3）

- 日期：2026-10-22
- 模型：deepseek-chat（两臂同一模型、同一 key）
- 预算：每任务 15 分钟；验收：独立脚本（判据先于运行定义）+ 完整性检查（不得改动既有测试）

## 结果

| 任务 | 单发直调 | 全管线 | 管线用时 | 备注 |
|---|---|---|---|---|
| schedule-jitter | ✅ 20s | ✅ 853s | 14.2min | 全管线含规划/并行/验收全流程 |
| tabulate-sort | ❌（实现错误） | ✅ 925s* | 15.4min | *到达验收上限时管线仍在收尾，但实现已合并、独立判据全部满足 |
| tenacity-attr-retry | ❌（输出非 JSON） | ❌ 916s | 15.3min | 变体竞争 3 worker 跨模型未在预算内收敛 |
| **合计** | **1/3** | **2/3** | | |

## 观察与诚实备注

1. **样本量 n=3，不做统计显著性结论**——首期只验证方法论与链路。
2. 单发臂两次失败模式很典型：输出被截断/非 JSON（无法落盘）、实现语义错误（能写代码但写不对）。
3. 管线臂的失败是预算内未收敛（变体竞争跨模型耗时），不是质量错误。
4. 管线的**独立验收**抓到了真实状态：tabulate 在 agent 仍在收尾时，验收脚本已确认判据满足——「验收不依赖 agent 自称完成」的设计生效。
5. 改进方向：增加「到达可验收状态的时间」（time-to-first-green）作为主指标，比固定预算更公平；任务数扩到 10+。
